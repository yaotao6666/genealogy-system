# 智慧族谱（太原堂王氏）· 项目介绍与部署指南

> 基于当前仓库代码梳理，部署与接口数据已于 Python 3.9.6 实测验证（2026-10-27）。

## 一、项目概览

| 项目 | 内容 |
|---|---|
| 项目定位 | 纸质族谱数字化的可运行演示系统 |
| 业务闭环 | 谱页拍照 → OCR 识别 → 结构化录入 → 族人/原谱双向关联 → 公开浏览 → 访客变更申请 → 管理员审核落库 |
| 系统形态 | H5 单页应用（手机优先，桌面为手机框演示）+ 深色大屏驾驶舱 + 单文件后端 |
| 技术栈 | Python 3 标准库（`http.server` + `sqlite3`）+ 原生 HTML/CSS/JS，**零第三方依赖** |
| 数据规模 | 30 代 / 20000 人 / 12 卷 / 7161 谱页 / 252 条待录入真值记录 |
| 默认端口 | 8787（环境变量 `PORT` 可改） |
| 管理员账号 | `admin / admin123`（演示账号，上线前必须修改） |
| 访问入口 | 浏览端 `/`；大屏驾驶舱 `/screen` |

目录结构：

```
family_tree/
  app/
    server.py       REST API + 静态服务 + 会话鉴权 + 可插拔 OCR 引擎
    seed.py         演示数据生成器（固定随机种子，可重复执行）
    verify_data.py  数据完整性校验（23 项 / 6 组）
    api_test.py     接口自动化测试（53 项，自起自停测试服务器）
    web/            H5 前端（index.html + app.css + app.js）
    web/screen.*    大屏驾驶舱
    data/           genealogy.db（SQLite WAL）+ photos/（谱页照片）
  prototype/        最初的高保真交互原型（设计稿，备查）
```

## 二、部署方式

### 1. 环境要求

| 项 | 要求 |
|---|---|
| Python | 3.9 及以上（实测 3.9.6） |
| 依赖安装 | 无，无需 `pip install` |
| 磁盘 | 演示数据数据库约 5.3 MB，另加谱页照片占用 |
| 端口 | 默认 8787，可通过 `PORT` 环境变量覆盖 |
| 浏览器 | 现代 Chrome / Edge / Safari；手机与服务器需网络互通 |
| 操作系统 | macOS / Linux / Windows 均可（仅依赖标准库） |

### 2. 方式一：本机演示部署（最快跑通）

```bash
cd app
python3 seed.py     # 首次初始化：生成 30 代 20000 人演示数据（约 1 秒）
python3 server.py   # 启动服务，默认 http://127.0.0.1:8787
```

- 浏览端：<http://127.0.0.1:8787>
- 大屏驾驶舱：<http://127.0.0.1:8787/screen>
- 管理端：浏览端右上角「管理员」→ `admin / admin123`

说明：

- `seed.py` 使用固定随机种子，可重复执行；重复执行会**重建数据库**（`app/data/genealogy.db`）。
- `server.py` 启动时若数据库不存在会直接提示先执行 `seed.py`。
- 修改端口：`PORT=9000 python3 server.py`。
- 服务监听 `0.0.0.0`，本机与局域网均可访问。

### 3. 方式二：局域网 / 现场部署（祠堂、宗亲会、祭祖活动）

适用于现场投屏 + 族人手机查阅，无需公网。

```bash
cd app
python3 seed.py
python3 server.py
```

1. 查询本机局域网 IP（macOS）：

   ```bash
   ipconfig getifaddr en0
   ```

2. 手机连接同一 Wi-Fi 后访问：`http://<本机IP>:8787`，页面自动全屏。
3. 投影/会议屏打开：`http://<本机IP>:8787/screen`。
4. 如无法访问，检查：同一网段、路由器是否开启 AP 隔离、系统防火墙是否放行 8787。
5. 现场建议为本机设置固定 IP，避免 DHCP 换址导致投屏地址失效。

### 4. 方式三：服务器常驻部署（长期使用）

#### 4.1 常驻进程

Linux（systemd 示例，`/etc/systemd/system/genealogy.service`）：

```ini
[Unit]
Description=Family Genealogy
After=network.target

[Service]
WorkingDirectory=/opt/family_tree/app
Environment=PORT=8787
ExecStart=/usr/bin/python3 /opt/family_tree/app/server.py
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now genealogy
```

macOS 临时常驻：

```bash
cd app
nohup python3 server.py > server.log 2>&1 &
```

长期运行建议使用 `launchd`（`~/Library/LaunchAgents/com.family.genealogy.plist`），配置 `ProgramArguments` 指向 `python3 /绝对路径/app/server.py`、设置 `WorkingDirectory` 与 `KeepAlive=true`，然后 `launchctl load -w` 加载。

#### 4.2 反向代理与 HTTPS（公网访问必做）

服务本身不带 TLS、无限流，**不要将 8787 直接暴露到公网**。使用 Nginx 反代并配置证书：

```nginx
server {
    listen 80;
    server_name genealogy.example.com;
    client_max_body_size 20m;          # 谱页照片上传

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

```bash
sudo certbot --nginx -d genealogy.example.com   # 申请并启用 HTTPS
```

注意：

- 前后端由同一服务提供，接口同源，**不要拆分跨域部署**；若必须拆分，需在反向代理层统一域名与路径。
- 照片上传大小由 `client_max_body_size` 控制，服务自身未做上传体积限制。

#### 4.3 容器化（可选）

仓库未内置 Dockerfile。如需容器化，可基于 `python:3.12-slim` 封装，挂载 `app/data` 为持久卷，并暴露 `PORT`；注意 `data/` 必须持久化，否则重建容器会丢失数据与照片。

### 5. 数据、重置与备份

数据全部落在本地文件：

| 路径 | 内容 |
|---|---|
| `app/data/genealogy.db` | 业务数据（SQLite，WAL 模式） |
| `app/data/genealogy.db-wal` / `-shm` | WAL 日志与共享内存，备份时需一并处理 |
| `app/data/photos/` | 上传的谱页照片 |

重置演示数据：

```bash
cd app
rm -f data/genealogy.db data/genealogy.db-wal data/genealogy.db-shm
python3 seed.py
```

在线安全备份（服务运行中也可执行）：

```bash
cd app
python3 - <<'PY'
import sqlite3
src = sqlite3.connect('data/genealogy.db')
dst = sqlite3.connect('data/genealogy.backup.db')
src.backup(dst)
dst.close(); src.close()
print('database backup ok')
PY
tar czf photos-backup.tgz data/photos
```

恢复时停止服务，用备份文件替换 `data/genealogy.db`（并删除旧的 `-wal/-shm`），再启动。

### 6. 接入真实 OCR

当前识别引擎为演示实现 `demo_ocr_engine`（[server.py](../app/server.py#L190-L224)）：它按谱页内置的「真值」还原识别结果，**调用契约与真实 OCR 一致**。接入生产引擎只需替换该函数，前端与接口不变。

返回结构：

```python
{
    'provider': 'baidu-ocr',            # 引擎标识
    'records': [{
        'name': '王承烈', 'zi': '仲远', 'gen': 12,
        'birth': '明成化二十年（1484）', 'death': '...',
        'father_name': '王...', 'spouse': '徐氏', 'intro': '...',
        'confidence': {'name': 0.98, 'zi': 0.83, 'birth': 0.76, ...},
    }],
    'message': '识别到 3 条齿录记录，请逐条核对后保存',
}
```

接入建议：

- OCR 调用放到独立函数或旁路服务，设置超时与失败兜底，避免阻塞请求线程；
- 保留 `confidence` 逐字段置信度（前端已按 <0.7 标红提示）；
- 确认保存时系统会创建族人、写入「族人-谱页」双向关联、按「姓名 + 上一世代」自动匹配父亲，并消费对应真值记录（[server.py](../app/server.py#L607-L656)）。

### 7. 上线前安全基线

1. **修改默认管理员密码**（在 `app` 目录执行，服务可运行）：

   ```bash
   python3 - <<'PY'
   import hashlib, sqlite3
   salt = 'gz2026'                 # 与 users 表当前 salt 保持一致
   pwd = '替换为你的强密码'
   h = hashlib.sha256((salt + pwd).encode()).hexdigest()
   c = sqlite3.connect('data/genealogy.db')
   c.execute('UPDATE users SET pwd_hash=? WHERE username=?', (h, 'admin'))
   c.commit(); c.close()
   print('password updated')
   PY
   ```

2. 公网部署必须启用 HTTPS，并限制 8787 仅本机监听（防火墙/反代）。
3. 当前为**单管理员模型**：写操作使用 Bearer Token，Token 存于浏览器 `localStorage`，无过期与限流机制；公网场景建议增加会话过期、登录限流与操作审计。
4. 大屏 `/screen` 为公开页面，请勿投放在含在世族人敏感信息的场景。
5. 定期备份 `genealogy.db` 与 `photos/`，并对备份做恢复演练。

### 8. 部署自检

```bash
cd app
python3 verify_data.py   # 数据完整性：23 项检查，退出码 0 为通过
python3 api_test.py      # 接口测试：53 项（会改动演示数据，跑完建议重新 seed）
```

快速验收：

```bash
curl -s http://127.0.0.1:8787/api/info
# 期望：members=20000, gens=30, pages=7161
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8787/
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8787/screen
# 期望：200 / 200
```

登录、拍照录入、审核通过/驳回、原谱翻页建议在部署后各走一遍。

## 三、功能介绍

### 1. 访客端（免登录）

| 模块 | 能力 |
|---|---|
| 首页 | 谱馆公告、族人/原谱/关联概况、四大入口（世系图/原谱/名录/申请变更）、大屏入口 |
| 世系图 | 按支逐级懒加载展开、双指/按钮缩放、点击人名查看详情；配偶记于人名下 |
| 族人名录 | 按世代筛选 + 姓名/字号/生平关键词搜索 + 分页（2 万级数据按需加载） |
| 族人详情 | 世代、字/号、生卒、配偶、父亲、子女、生平、关联原谱缩略图与资料来源 |
| 原谱阅览 | 12 卷目录、翻书动效、左右滑动/点击翻页、本页关联族人、查看拍摄原图 |
| 申请变更 | 三类申请：修改信息、新增族人、纠正关联；可填申请人、佐证说明、上传佐证图片；支持匿名提交 |
| 大屏入口 | 一键打开 `/screen`，用于祠堂或会议投屏 |

### 2. 管理端（登录后）

| 模块 | 能力 |
|---|---|
| 工作台 | 待审核提醒、谱馆概览、待录入真值提示、快捷入口、适老字号设置 |
| 拍照录入 | 四步向导：拍摄/选图 → 选卷页（自动定位第一个未录入页）→ OCR 识别并逐字段核对（低置信标红、多记录分页签）→ 勾选保存（建人 + 建关联 + 自动匹配父亲 + 可选关联已有族人） |
| 族人维护 | 搜索、新增、编辑、删除；存在子女记录时禁止删除 |
| 变更审核 | 待处理/已处理分组；通过时按申请类型实际落库；驳回必须填写理由；重复处理会被拦截 |
| 原谱管理 | 按卷查看页码关联状态网格，查看/替换谱页照片，跳转录入关联，取消关联 |

### 3. 大屏驾驶舱（`/screen`）

面向祠堂、会议、展览投屏的深色数据大屏，数据来自 `/api/screen` 聚合接口：

- **可折叠世系树**：滑杆控制「展开至 N 世」，节点按支展开/收起；点击「主要支系」排名可重定位树根，一键回到始祖；支持全谱搜索定位族人。
- **族人明细联动**：点击树中任意人名，右侧展示生卒、字号、配偶、父亲、生平、关联原谱页；点击世代人口柱形查看该世名录。
- **统计图表**：朝代分布、世代人口金字塔、主要支系后嗣排名、页面关联率环形图、协作进度。
- **谱馆介绍**：首屏自动展示缘起与驾驶舱用法，可随时重看。

### 4. 数据规模与性能

- 30 代 20000 人（唐咸通年间始祖 → 清道光），12 卷 7161 页，120 页残页 / 252 条待录入真值记录。
- 列表、搜索、世系树均为按需分页与懒加载；2 万级关键词搜索接口实测约 16–30 ms/次（含 HTTP 开销）。
- 后端使用 `ThreadingHTTPServer` + SQLite WAL：读并发表现良好，写操作串行；适合数十人规模的谱馆日常使用，不适合高并发写入。
- `seed.py` 内置自检，`verify_data.py` 覆盖规模、树结构、时间、页面、真值、业务共 23 项校验。

### 5. 体验与适老化

- 「中式雅致」视觉：宣纸底色、朱印、宋体标题。
- 全站三档字号（标准/大字/特大），即时生效并本地记忆。
- 大点击区域、关键操作二次确认、操作结果 Toast 提醒、分步向导降低录入门槛。
- 支持系统「减弱动态效果」偏好；手机访问自动全屏。

## 四、适配场景

### 1. 核心适配（可直接使用）

| 场景 | 适配理由 |
|---|---|
| 宗族祠堂 / 谱馆数字化 | 纸质老谱逐页拍照 → OCR 简化录入 → 族人/原谱双向关联，形成可查、可翻、可纠错的数字谱馆；大屏适合祠堂展示 |
| 修谱项目 / 宗亲会协作 | 残页待录入清单明确，志愿者用手机即可拍照辨认；访客可提交纠错与补录申请，管理员统一审核，避免直接改库 |
| 文化馆 / 档案馆 / 地方志 / 姓氏文化展 | 大屏驾驶舱展示世系、人口与朝代分布；观众用手机扫码/局域网访问即可查阅，无需安装 App |
| 教学、毕业设计、技术方案验证 | 零依赖、单文件后端、SQLite，一条命令跑通完整业务闭环；OCR 引擎可插拔，便于替换真实引擎做对比实验 |
| 祭祖、颁谱、宗亲会等现场活动 | 局域网即可部署，手机全屏浏览 + 投影大屏，无需公网与额外基础设施 |

### 2. 有条件适配（需少量改造）

| 场景 | 改造点 |
|---|---|
| 师徒谱系、技艺传承谱、组织沿革 | 数据模型可复用（世代 + 父级 + 配偶/传承人），需调整字段语义与界面文案 |
| 小型档案全文检索 | 当前为 SQLite `LIKE` 模糊匹配，数据量增大后建议引入 FTS5 或外部搜索引擎 |
| 多管理员 / 多谱馆 | 需增加多租户隔离与 RBAC 权限、操作审计；当前为单管理员模型 |
| 已有谱牒数据导入 | 需新增导入脚本/接口，将 Excel、GEDCOM 或既有数据库映射到现有表结构 |
| 内外网隔离部署 | 需自行增加静态资源离线化与照片存储方案；当前依赖服务端接口 |

### 3. 不适配或需重构（不建议直接上线）

| 场景 | 原因 |
|---|---|
| 公网高并发 / 多租户 SaaS | 标准库 HTTP 服务 + 单机 SQLite，缺少连接池、缓存、水平扩展与限流能力 |
| 要求生产级 OCR 精度 | 仓库内置的是演示识别引擎，必须替换为真实 OCR/视觉模型并配套人工复核 |
| 原生 App / 完全离线编辑 | 当前是 H5 在线应用，仅支持浏览与拍照上传，不支持离线录入与同步 |
| 含大量在世族人敏感信息 | 缺少字段级权限、脱敏、访问审计；大屏为公开页面，需评估隐私合规 |
| 高可用、自动容灾、审计合规 | 无集群、无自动备份、无操作日志，需额外运维与开发 |

### 4. 选型速查

| 你的目标 | 建议部署方式 |
|---|---|
| 先看效果、做演示 | 方式一：本机 `seed + server` |
| 祠堂现场、宗亲会投屏 | 方式二：局域网 + 手机访问 + `/screen` |
| 长期给族人使用 | 方式三：服务器常驻 + Nginx + HTTPS + 定时备份 |
| 教学/毕设/接口联调 | 临时目录跑 `seed.py`、`verify_data.py`、`api_test.py` |

## 五、当前边界与演进建议

**已知边界**

- OCR 为演示引擎，识别结果来自内置真值，不代表真实识别准确率。
- 单管理员、Token 无过期、无登录限流、无操作审计。
- SQLite 单机存储，照片存本地磁盘，未接对象存储。
- HTTP 服务无 TLS、无上传大小限制，需依赖反向代理补齐。
- 无 Dockerfile、无 CI、无自动化部署脚本。

**建议演进顺序**

1. 接入真实 OCR 引擎，建立「识别 → 低置信复核 → 人工确认」的质控流程。
2. 增加会话过期、登录限流、操作审计与多管理员权限。
3. 补齐自动备份、健康检查与监控告警。
4. 数据量或并发增长后，再评估迁移 PostgreSQL、对象存储与独立前端部署。
